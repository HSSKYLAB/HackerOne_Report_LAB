# Mozilla Pontoon 저장형 XSS 취약점
## 1. 개요
대상 시스템: Mozilla Pontoon (공개 대시보드)

취약점 유형: 저장형 크로스 사이트 스크립팅 (Stored XSS)

보고자: TIMHAINES

심각도: 높음 (High)

## 2. 취약점 발생 원리 (How it Works)
취약한 데이터 처리 방식 (문자열 연결 및 jQuery .after() 사용):

Pontoon 공개 대시보드의 최신 활동 툴팁은 기여자가 입력한 data-* 속성 값을 문자열로 연결하여 jQuery의 .after() 함수에 전달하는 방식으로 HTML 마크업을 생성했습니다.

이때 번역 텍스트에 대해서만 별도의 인코딩 처리가 이루어졌습니다.

서버 인코딩과 브라우저 디코딩의 차이 (이중 디코딩 이슈):

서버 측에서는 입력값을 HTML 속성에 넣을 때 이스케이프 처리를 거쳤습니다.

하지만 브라우저는 jQuery가 해당 속성 값을 읽기 전에 속성 내부의 값을 자동으로 디코딩하기 때문에, 결과적으로 인코딩되지 않은 원본 악성 마크업이 그대로 반환되었습니다.

악성 페이로드 주입 경로:

Pontoon의 로컬 계정 가입 기능은 표시 이름(Display Name)이 없을 경우 계정의 이메일 주소를 화면에 표시합니다.

이 기능은 <script>alert(document.domain)</script>x"@example.org와 같은 형태의 특수한 이메일 주소로 가입하는 것을 허용했습니다.

## 3. 공격 시나리오 (PoC 흐름)
계정 생성: 공격자가 악성 스크립트가 포함된 이메일 주소로 로컬 계정을 생성합니다.

데이터 저장 (Store): 해당 계정으로 일반적인 번역 제안 활동을 수행하면, 시스템에 악성 스크립트가 포함된 활동 데이터가 저장됩니다.

트리거 및 실행: 로그인 여부와 상관없이 공개 대시보드의 해당 활동 셀에 마우스를 올리는(Hover) 모든 사용자의 브라우저 세션에서 악성 스크립트가 실행됩니다.

## 4. 영향력 (Impact)
번역가 세션: 공격자가 제안한 번역 내용을 임의로 승인할 수 있습니다.

로케일 관리자(Locale Manager) 세션: 공격자 계정을 해당 로케일 관리자 그룹에 강제로 추가하여 지속적인 권한을 획득할 수 있습니다.

## 5. 조치 내역 (Remediation)
모질라 측은 다음과 같은 다중 방어선(Defense-in-Depth) 패치를 적용하여 취약점을 해결했습니다:

로컬 가입 경로 제거 (mozilla/pontoon#4482, 2026년 9월 2일)

CSP(Content Security Policy) 복원: 인라인 스크립트 실행을 차단하는 보안 정책 적용 (mozilla/pontoon#4493, 2026년 9월 3일)

DOM 노드 생성 방식으로 변경: 문자열 연결 방식 대신 안전한 DOM 노드 생성 방식을 사용해 툴팁을 생성하도록 코드 수정 (mozilla/pontoon#4583, v2026.10.08 릴리스)
